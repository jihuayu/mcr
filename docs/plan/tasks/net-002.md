# net-002: Implement Level-Triggered Poll And Epoll Readiness

## Objective

Implement the Phase 2 level-trigger readiness subset for `poll`, `ppoll`, `epoll_create1`, `epoll_ctl`, and `epoll_wait` over sockets, pipes, stdio, proc/dev virtual nodes, and internal runtime wakeups.

## Context

- `docs/architecture/runtime.md`

## Path

- `crates/mcr-net/`
- `crates/mcr-vfs/`
- `crates/mcr-sys/`
- `crates/mcr-runtime/`

## Verification

```powershell
cargo test -p mcr-net
cargo test -p mcr-vfs
mcr run-rootfs alpine-rootfs /bin/sh -c "curl -fsSL https://example.com >/dev/null"
```

## Notes

- Use Winsock/`WSAPoll` or simpler host readiness helpers first; IOCP optimization is deferred.
- Include timeout, removed watch, closed fd, pipe readiness, stdio/proc/dev readiness, and socket readiness tests.
- Support the event bits needed by the Phase 2 smoke matrix: `POLLIN`, `POLLOUT`, `POLLERR`, `POLLHUP`, and matching epoll bits.
- Edge-triggered epoll, `EPOLLONESHOT`, `EPOLLEXCLUSIVE`, and signal-mask behavior beyond the documented subset must fail with explicit Linux-compatible errors instead of being accepted silently.
- The HTTPS smoke must exercise readiness through the guest shell path.
