# net-002: Implement Level-Triggered Poll And Epoll Readiness

## Objective

Implement the Phase 2 level-trigger readiness subset for `poll`, `ppoll`, `epoll_create1`, `epoll_ctl`, and `epoll_wait` over sockets, pipes, stdio, proc/dev virtual nodes, and internal runtime wakeups.

## Context

- `docs/architecture/runtime.md`
- `docs/architecture/networking.md`

## Path

- `crates/mcr-net/`
- `crates/mcr-vfs/`
- `crates/mcr-sys/`
- `crates/mcr-runtime/`

## Verification

```powershell
cargo test -p mcr-net
cargo test -p mcr-vfs
cargo test -p mcr-runtime poll_ -- --nocapture
cargo test -p mcr-runtime epoll_ -- --nocapture
gh workflow run x86-runtime-smoke.yml -f suite=network
```

## Notes

- Use the semantic-first backend from `docs/architecture/networking.md`:
  nonblocking Winsock sockets plus runtime readiness/wait handling first. IOCP
  optimization is deferred and must not become the guest-visible epoll model.
- Include timeout, removed watch, closed fd, pipe readiness, stdio/proc/dev readiness, and socket readiness tests.
- Support the event bits needed by the Phase 2 smoke matrix: `POLLIN`, `POLLOUT`, `POLLERR`, `POLLHUP`, and matching epoll bits.
- Edge-triggered epoll, `EPOLLONESHOT`, `EPOLLEXCLUSIVE`, and signal-mask behavior beyond the documented subset must fail with explicit Linux-compatible errors instead of being accepted silently.
- The HTTPS smoke must exercise readiness through the guest shell path.
- Local unit coverage now exercises the readiness queue behavior directly; the remaining gate is end-to-end native x86 guest execution through the network smoke suite.
- Do not use Alpine host-shell smoke as verification for this task. Final proof belongs to the GitHub Actions/QEMU-native x86 path, and remains coupled to `net-001` DNS/integration completion.
