# jit-002: Track Dynamic Executable Pages And Native Fault Signals

## Objective

Make native execution safe for guest-generated executable code by tracking
dynamic `PROT_EXEC` ranges, invalidating patched ranges after executable writes,
and mapping host faults from guest code back into Linux signals.

## Notes

- `mmap`/`mprotect` that add `PROT_EXEC` must invalidate native patch metadata
  for the affected range and make the next native entry scan newly executable
  code.
- Writes to executable or RWX pages must conservatively invalidate the affected
  translated/native-patch range before it can execute again.
- Host-side code patching and guest writes that affect host-executed
  instructions require `FlushInstructionCache` on Windows.
- Windows SEH/VEH faults from guest-owned addresses must become thread-pending
  Linux signals such as `SIGSEGV`, `SIGBUS`, `SIGILL`, or `SIGFPE`, then reuse
  the return-to-user signal delivery path from `task-004`.
- This task does not try to make Node/V8 green by hiding fatal signals; default
  fatal actions must still terminate the guest process with Linux-compatible
  status.
