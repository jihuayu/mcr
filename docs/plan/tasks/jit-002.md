# jit-002: Track Dynamic Executable Pages And Native Fault Signals

## Objective

Make native execution safe for guest-generated executable code by tracking
dynamic `PROT_EXEC` ranges, invalidating patched ranges after executable writes,
and mapping host faults from guest code back into Linux signals.

## Notes

- Closed with dynamic executable-page invalidation for guest writes: `GuestMemory`
  now records a generation when writable executable bytes are changed, and the
  native patch cache invalidates before the next native entry observes stale
  syscall/FS metadata.
- Host-side patching and guest writes that touch host-executed bytes now flush
  the Windows instruction cache for the affected host allocation range.
- `mmap`/`mprotect`/`munmap` invalidation remains range-based; guest writes are
  deliberately conservative and invalidate the cached executable metadata by
  generation.
- Windows native faults still deliver installed guest `SIGSEGV` handlers through
  the Linux signal frame path. Privileged-instruction faults such as V8 `hlt`
  now take the default fatal `SIGSEGV` action instead of escaping as a host
  native execution error. Plain access-violation faults without a guest handler
  continue to surface as native diagnostics so unsupported native windows can
  still fall back through the existing `ENOEXEC` path.
- This task does not special-case Node/V8 or suppress fatal signals.
